# Design

## Context

參照 [proposal.md](proposal.md) 與四份能力規格。本 repo 原先沒有應用程式骨架；目標是本機單程序 Flask 應用。Google Sheets 需要讀取合併範圍與儲存格位置，且匯出前必須確認來源結構未變。學生加入不使用密碼，因此伺服器端的角色範圍查詢是資料保護邊界。

## Goals / Non-Goals

**Goals:**
- 用單一 Flask 程序和本機 SQLite 支援完整活動生命週期與重啟恢復。
- 以可替換 Sheets adapter 隔離 Google API，讓自動化測試完全離線。
- 所有順位和可見性判斷在伺服器端完成。

**Non-Goals:**
- 多程序／多主機部署、外部託管服務、Google 帳號登入或跨活動管理平台；不提供公網部署承諾。
- 自動辨認沒有明確「題號」及「作答」結構的任意工作表版型。
- 自動化測試呼叫真實 Google API；真實授權與雲端寫入另列人工驗證。

## Decisions

### Flask 分層與本機儲存

- 使用 Flask route 作為 HTTP 邊界，將活動服務、題目解析、順位計算與匯出協調器放在可單元測試的服務模組。頁面使用 Jinja HTML 與原生 JavaScript；瀏覽器每 1 秒輪詢階段和該角色可見的資料。
- Flask 啟動 host 可設定，預設為 `0.0.0.0`，並提供 `--host` 命令列參數；README 說明如何查本機區網 IP，讓同一區網的學生連入。此設定不代表支援公網部署。
- 使用 SQLite 保存活動、組別、題目、填空位置、提交紀錄與單調遞增序號，啟用 WAL journal mode 與 busy timeout。每次接受提交在單一交易內新增紀錄並分配全域序號；用每組每題最新紀錄計算有效答案與排名。保留提交歷史可追溯重送，排名以最新紀錄而非最早紀錄為準。並行提交測試須確認序號唯一且接受順序一致。
- 在本機 `instance/` 放置資料庫及 Google 使用者憑證／token，並在 `.gitignore` 明確排除。密碼使用 Werkzeug 的安全密碼雜湊函式；不得保存明文。
- 活動代碼使用隨機、可輸入的大小寫不敏感字元組合，建立時檢查 SQLite 唯一性；驗證以活動 ID 綁定 Flask session。學生 session 僅記錄活動與組別 ID，不建立新組別資料，重新輸入相同組別編號即回到同一組。

### 階段同步與資料可見性

- 使用 `GET` 狀態端點每秒輪詢，回應包含伺服器階段及更新版本。目標是在本機正常連線時讓階段於 2 秒內更新；網路錯誤時保留頁面並顯示連線狀態，恢復後以伺服器狀態覆蓋。
- API 依 session 角色與活動階段組裝回應。學生在準備／搶答中只回傳本組資料；結束後只回傳每題成功組答案、成功組別及學生本組的答案與順位。老師端需驗證密碼 session 才可取得監看與全提交資料。不要依賴前端隱藏 DOM 遮蔽資料。
- 準備階段的學生頁面不顯示題目；搶答中可回傳全部題號與各題填空數，不回傳題目敘述或他組作答。準備階段未匯入至少一題時，服務端拒絕開始搶答。
- 提交端點從路由載入題目填空數，服務端驗證整筆答案、階段及字數，再於 SQLite 寫入新序號；不得接受客戶端提供的順位、時間或有效序號。

### Google Sheets adapter 與動態解析

- 定義窄介面，例如 `read_structure(sheet_url)` 回傳試算表 ID、工作表 ID/title、格值、合併範圍與座標，`write_answers(sheet_id, updates)` 執行一批純文字更新。正式 adapter 使用 Google 官方 Python API 套件；測試注入記憶體假 adapter。
- 解析器先掃描格值，唯一定位同一標題列的「題號」和「作答」欄；標題不存在、重複或分屬不同列時回報工作表與座標。從標題列下方掃描，題號儲存格若在合併範圍內，該題號套用到範圍內作答列；非合併空白題號不自行猜測歸屬。每一個可定位作答格形成一個填空，按工作表列順序歸屬到題號。題數由唯一題號計算。
- 匯入時保存標準化結構快照：來源 spreadsheet／工作表識別、題號順序、每題填空順序與每格座標。匯出時重新讀取並解析，再比較標準化快照；任何題號、填空數、順序、工作表或座標改變即在寫入前中止。
- 對通過比對的成功組答案，adapter 以 Google Sheets `batchUpdate` 的單一批次更新呼叫，使用 `updateCells` 與 `userEnteredValue.stringValue` 寫純文字，欄位遮罩僅指定 `userEnteredValue`，避免覆蓋儲存格既有格式。只生成有成功提交的題目之格更新，避免覆寫無人作答的格。若服務回報錯誤，不回報匯出成功，保留本機活動資料。

### 測試策略與憑證

- 使用 pytest；測試的 Sheets adapter fixture 預設為假實作，並讓測試在沒有憑證和網路的乾淨環境可執行。
- 解析器測試以不同標題位置、題組合併儲存格、混合題型、缺漏／重複標題及模糊題號格覆蓋驗收情境。服務／路由測試覆蓋階段、整題提交、重送序號、學生資料可見性、老師監看、結束後結果及結構變更中止。
- README 說明建立 Google Cloud 專案、啟用 Sheets API、建立桌面 OAuth 用戶端、把憑證放入被忽略的 `instance/` 路徑、授權本機使用者及分享 Sheet 的方式。文件中不得放真實憑證或金鑰。
- README 說明如何查本機區網 IP，並以該 IP 組成學生可開啟的位址；人工驗證跨裝置區網連線。不得將此描述成公網部署支援。
- 人工驗證使用者自建憑證，確認連結權限、讀取合併範圍、純文字回寫且保留儲存格格式，以及 Google API 錯誤呈現；不得要求自動測試存取真實帳戶。

## Risks / Trade-offs

- 本機 SQLite 損壞或使用者刪除資料會失去活動與順位 → README 說明備份資料庫；匯出前另提醒備份 Sheet。
- Google API 無法保證網路失敗時使用者能判斷雲端是否已收到寫入 → 使用批次更新、提供錯誤細節，並讓重試前重新讀取結構與結果；不標示成功直到 API 回應成功。
- 啟動預設綁定 `0.0.0.0` 會讓本機網路介面可連入，且學生身分不需密碼 → README 說明只在可信任的本機區網使用、不提供公網部署承諾；知道活動代碼與組別編號的人可重新進入該組，這是已確認的使用規則。
- 格式不一致或有多個可能題號的 Sheet 無法安全猜測 → 明確列出工作表與座標要求老師修正後再匯入。
- 多題提交同時到達時需要序號唯一性，SQLite 可能遇到寫入競爭 → 使用 WAL、設定 busy timeout、原子化交易與單調計數器更新，並以並行提交測試驗證。

## Migration Plan

此為全新本機應用，沒有舊版資料遷移。啟動時建立 SQLite schema；版本更新若新增 schema 欄位，須以版本化 migration 保留既有活動。回滾程式版本時保留並先備份本機資料庫，避免使用不相容 schema。
