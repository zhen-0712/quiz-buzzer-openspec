# Design

## Context

現有 Guided Notes parser 從傳入的工作表集合中尋找標題，目前多個候選工作表會直接被判定為歧義。匯入結構快照已包含工作表 ID；匯出需使用該 ID 重新解析，避免工作表順序或後續新增工作表改變匯出目標。結束後老師資料目前同時包含歷史提交與目前有效提交。學生頁面每秒輪詢並重畫題目區，送出流程持有的舊 DOM 表單可能已被替換。

## Goals / Non-Goals

**Goals:**
- 將多工作表選擇、`gid` 限定、重複題號與匯出目標固定化。
- 讓老師結束畫面聚焦於每組每題最新有效答案，同時保留資料庫提交歷史。
- 讓學生成功或失敗後能重新送出，且輪詢不丟失尚未送出的答案草稿。
- 清除指定誤提交資料庫並避免再次追蹤。

**Non-Goals:**
- 不改變題目填空、順位判定、學生可見性或 Google Sheets 寫入格式規則。
- 不移除提交歷史或新增多程序／雲端部署支援。
- 不在此提案階段修改程式、README、對照表或刪除資料庫檔。

## Decisions

### 工作表選擇與題號區塊

- adapter 保留 Google API 回傳的工作表順序。匯入時若連結含 `gid`，adapter 僅回傳該 ID 的工作表；若未指定，parser 依順序略過沒有同一列完整「題號」與「作答」標題的工作表，選第一個符合者。
- 選定工作表後才做完整解析。若該表有多個完整標題列、重複標題、無法歸屬的題號／填空或重複題號，直接回報工作表與位置，不嘗試下一個工作表。沒有任何候選工作表時，回報未找到可用標題。
- 將每個連續題號區塊視為一題。題號合併範圍內跨越的列只算同一區塊；題號區塊結束後再次出現先前題號即拒絕，訊息同時指出首次與再次出現的位置。此規則避免將不相鄰的同號題誤併成同一題組。
- 在匯入 transaction 前完成解析。解析失敗不寫入題目、來源 URL 或結構快照，既有匯入資料保持不變。

### 匯出固定比對匯入工作表

- 匯入快照的 `worksheet_id` 是匯出時的選擇依據。讀取介面允許指定工作表 ID；若來源 URL 已含 `gid`，必須與快照 ID 一致。匯出只讀取／解析該工作表，再比較來源、題號、填空順序與座標。
- 匯入後新增、重排或修改其他工作表，不得令匯出切換目標；若記錄的工作表不存在、指定不一致或結構變更，維持既有規則：停止且零寫入。

### 最新有效提交與相同答案重送

- 每次通過驗證的提交都建立新歷史紀錄並使用新的伺服器序號，即使答案內容與前次完全相同。
- 結束後老師的提交表格投影只呈現每組每題最新有效提交；順位仍依每組該題最新序號計算。資料庫歷史不刪除，既有歷史保留測試可確認舊紀錄仍存在。

### 學生題目表單與輪詢草稿

- 每題以題號維護送出中的狀態，只有請求處理期間停用按鈕；請求完成後釋放狀態，並更新目前畫面上該題的新表單，不操作已被重畫替換的舊 DOM 節點。
- 重畫題目區前擷取所有未送出輸入值，以題號及填空位置索引；重畫後還原。成功送出的題目清空，失敗題及其他題保留原草稿。
- 先使用現有 pytest／靜態檢查評估前端自動化能力；若無法執行 JavaScript，依 README 的人工步驟驗證成功、失敗、按鈕恢復和跨題草稿保留，不為此引入前端建置工具。

### 誤提交 SQLite 檔與忽略規則

- 實作任務使用 `git rm -- "貼上視窗 A 的資料庫路徑"` 移除指定追蹤檔，不讀取其內容。
- `.gitignore` 保留通用資料庫規則，並補足根目錄此無副檔名路徑的明確忽略規則（若檔案名稱可能再次產生），以 `git check-ignore` 驗證暫存 DB 與該路徑。

## Risks / Trade-offs

- 工作表被選定的規則若不一致，可能匯入到錯的分頁 → 固定採第一個完整標題列，保留 API 工作表順序，並保存工作表 ID。
- 題號區塊的重複判斷對不規則版型較嚴格 → 回報首次與再次位置，要求老師修正後重匯。
- 前端目前沒有明顯的 JavaScript 測試執行器 → 優先用現有能力自動化；不足處以可重現手動步驟補足。
- 刪除指定資料庫檔會移除該檔本身 → 任務只針對明確命名的誤提交檔，並在 git diff 檢查刪除目標。

## Migration Plan

此變更不需資料庫 schema migration。部署後保留既有提交歷史；parser/import/export 只改變工作表選擇和驗證行為。刪除根目錄誤提交檔並保留使用者本機 `instance/` 資料不在本變更範圍。

## Open Questions

無。工作表選擇依序、題號區塊判定、相同答案重送與草稿保留規則已在需求中明確指定。
